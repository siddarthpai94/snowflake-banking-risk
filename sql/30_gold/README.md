# sql/30_gold: canonical banking model and risk engine (F2, F4, F14)

Run in this order with `snow sql -c default -f <file>`:

| File | What it does |
| --- | --- |
| `30_config.sql` | `GOLD.CONFIG_PARAM` and `GOLD.CONFIG_RISK_RULE` from `config/bank_demo.yaml` (generated by `scripts/emit_config_sql.py`; do not edit by hand) |
| `31_gold_core.sql` | `PARTY`, `ACCOUNT`, `LOAN`, `TRANSACTION`, `ALERT`, `KYC_PROFILE`, `BRANCH` as dynamic tables. Column logic follows `config/mappings/core_*.yaml`; `party_id` comes from `SILVER.PARTY_XREF`; every row keeps `source_file` and `source_row` |
| `32_risk_engine.sql` | `RISK_SIGNAL` (fired rules with evidence), `RISK_SCORE` (weighted score and top reasons), `ALERT_QUEUE` (ranked investigator queue) |
| `90_customer_360_proof.sql` | Thursday proof: Deborah Sanford across both cores with accounts, loans, cash, KYC, alerts and risk signals |
| `91_eval_risk.sql` | F4 acceptance against the injected patterns (needs the EVAL schema); last lines should say `PASS` and show Deborah Sanford first |
| `92_golden_check.sql` | Answers the 15 golden questions from Gold only; compare with `docs/spec.md` |

No AI is used anywhere in this folder. Thresholds and weights live in config, so a second bank runs from its own YAML with no SQL change (`tests/test_f4_gold_risk.py::test_thresholds_come_from_config_not_code`).
